# Section Definitions

This file defines the rule categories for code leverage best practices. Rules are automatically assigned to sections based on their filename prefix.

---

## 1. Leverage Mindset (mindset)
**Impact:** CRITICAL
**Description:** Foundational thinking — lines of code as liability, thinking in primitives over features, asking the right questions before writing any code.

## 2. Abstraction Design (abstraction)
**Impact:** CRITICAL
**Description:** The Three Cs (Composable, Constraining, Complete), vocabulary layers, extraction decision framework. Getting abstractions right is the highest-leverage skill.

## 3. Minimum Code Patterns (pattern)
**Impact:** HIGH
**Description:** Convention over configuration, schema-driven development, registry pattern, pipeline composition, configuration as extension point, declarative over imperative.

## 4. System Boundaries (boundary)
**Impact:** HIGH
**Description:** Internal APIs as products, DRY across service boundaries, platform mentality. Treating every interface as a multiplication point.

## 5. Code Reduction (reduce)
**Impact:** MEDIUM-HIGH
**Description:** Eliminating states, branching, and ceremony. Reducing the state space, using polymorphism over conditionals, leveraging language features aggressively.

## 6. Review Lens (review)
**Impact:** MEDIUM
**Description:** Five-check review framework — existence, placement, shape, minimum, and composability. Applied in order when reviewing or writing code.
